# 桌面客户端多服务器连接

## 实现方案

1. 桌面登录页及首次初始化页显示当前服务器和「设置服务器」入口，仅在原生桌面窗口中启用。
2. 首次启动直接显示本地运行模式选择窗口，选择远程后才显示地址设置；主登录窗口在连接成功后显示。启动、模式和服务器页面统一使用登录页的品牌色、圆角及控件样式。
3. 地址列表及默认选择写入 `OCTOP_HOME/desktop-servers.json`，跨域共享并在重启后恢复；账号登录沿用各服务器原有流程。
4. 切换前校验地址并请求 `/api/health`；连接失败保留此前选择。启动优先使用保存的选择，其次兼容 `OCTOP_DESKTOP_URL`；都没有时显示连接选择页，等待用户选择。
5. 本地模式、远程模式切换时取消旧的启动任务，只停止客户端自己启动的 Python 子进程。
6. 默认远程服务不可用时提供重试、切换服务器和临时使用本地。临时本地只改变当前会话，保留远程默认地址，重启后继续连接远程。

远程登录页的原生事件仅允许打开设置窗口。保存、删除和切换通过本地设置窗口的绑定方法完成。
地址只支持 HTTP/HTTPS 服务器根地址，不接收账号密码、查询参数或脚本协议；列表不保存登录凭据。

## 使用

1. 首次打开客户端，直接在运行模式页选择「远程服务器」或「本地模式」。选择本地才准备并启动本地服务；登录页、首次初始化页和客户端启动页保留「设置服务器」入口。
2. 选择远程后输入地址，例如 `https://work.hivekernel.com`，名称可选，点击「保存并连接」直接进入远程登录页。需要先保存多个地址时使用「仅保存」。
3. 已保存地址可在「选择服务器」中切换，并点击「连接并设为默认」。添加表单及已保存列表默认折叠，按需展开编辑、删除；「运行模式」入口可返回选择本地。
4. 下次启动自动恢复该选择，不需要再次输入地址。需要切换时重新打开设置并选择其他服务器。

各服务器使用其自己的账号登录。本地服务也是一个可选择的连接目标。
地址只接受 HTTP/HTTPS 根地址，不支持 `/work` 等部署前缀、账号密码或查询参数。
浏览器访问和旧版桌面客户端隐藏此入口；需要同时使用新版桌面程序和更新后的服务端前端。

已设为默认的条目可以修改名称。修改其地址或删除前，需要先把其他服务器或本地服务设为默认；临时本地连接不会解除默认地址的保护。
连接失败时显示错误，保留原来的默认地址；本地服务同样在启动成功后才保存默认选择。
文件损坏或读取失败时显示错误并保留原文件，修复文件后重新启动客户端。

## 本地保存与兼容性

登录页只显示当前「线路名称 - 地址」，不再展开服务器卡片或说明文字。
右侧「设置」采用现有 AntD 小号描边按钮、齿轮图标和悬停提示，点击打开客户端内置的服务器设置页。
长线路使用单行省略，悬停可查看完整内容；更改当前线路名称后立即更新。
原生桥只向当前页面提供这一条线路的名称和地址，不公开其他已保存线路。

桌面端偏好中的「设置服务器」位于设置列表末尾，以整行菜单和右箭头进入服务器设置页。
底部仅保留「显示蜂巢智工」和「退出」；窗口高度随新增菜单增加，已核对中英文内容完整可见。
默认主题为科技蓝（`tech`），桌面设置和运行模式页的按钮、悬停及焦点配色与之统一。
已保存的 Web 主题偏好继续优先加载。
同版本内置运行时通过 wheel `RECORD` 识别资源变化，必要时沿用数据库备份与原子替换流程。
本地已有更高版本不会降级；无 `RECORD` 的旧包仍按原兼容规则处理。

配置位于 `~/.octop/desktop-servers.json`；设置了 `OCTOP_HOME` 时使用该目录。
该文件独立于桌面偏好 `desktop-settings.json`，保存列表时不会修改账号、密码或登录令牌。
文件使用临时文件替换的方式保存；自动化测试使用隔离目录验证重读及保存失败的处理。

```json
{
  "servers": [
    { "name": "蜂巢智工云端", "url": "https://work.hivekernel.com" },
    { "name": "测试环境", "url": "https://work.example.com" }
  ],
  "activeUrl": "https://work.hivekernel.com"
}
```

`activeUrl` 为 `null` 表示尚未选择，继续兼容 `OCTOP_DESKTOP_URL`；
空字符串表示明确选择本地服务，非空字符串表示默认的远程服务器。
保存的选择优先于环境变量。未选择且没有环境变量时等待选择，不探测本地服务、不解压运行时、不启动 Python 或创建本地数据库。

远程模式只校验并打开远程地址，不调用本地运行时准备和服务启动流程。
明确选择本地后优先复用已有本地服务；没有可复用服务时才解压运行时并启动后端。
远程连接失败不会自动回退本地，以免进入另一套账号、数据库和工作区。
点击「临时使用本地」不会修改 `desktop-servers.json`；下次启动仍使用保存的远程选择。

远程页面只通过原生事件打开管理窗口。列表读取、保存、删除和切换要求绑定调用的
窗口身份为本地 `server-manager`，其他窗口调用会被拒绝。
重试和临时本地操作也受同一窗口权限限制。主窗口的连接状态事件只携带阶段和错误提示，不广播保存的服务器列表。
连接检查请求 `/api/health`，不发送登录凭据，并保留 TLS 证书校验。
切换时只停止客户端自己创建的后端子进程，已存在的独立本地服务不会被停止。

新增功能集中在 `desktop/src/servers.go`、`server_connections.go` 和本地管理页面，
登录页、初始化页共用 `DesktopServerSettings` 组件；无需修改后端 API 或数据库结构。
应用安装身份、包名和既有环境变量名称保持兼容，方便后续合并上游。
